# SSClip发送：单快捷指令、每次选择设备

## 本次修复
用户实机已确认状态文件实际为 `.txt`，旧版却读取 `.json`，导致每次重新要求选择配置。这次统一为 **iCloud Drive/Shortcuts/SSClip/connection-state.txt**，文件内容仍是 JSON，不需要重置 API Key。

- 现有 `connection-state.txt` 直接沿用，不要求重新导入。
- 仅在该文件缺失时依次兼容精确旧名 `connection-state.json.txt`、`connection-state.json`；版本、URL、Key 验证后才使用。旧文件不会自动迁移、覆盖或删除。
- 新保存前通过原生 Set Name 显式命名 `connection-state.txt`，保存路径也使用同一文件名。
- 保存后只读取 canonical `.txt`，不回退旧文件；格式、版本、地址、Key 全部一致才显示“连接已保存”。旧文件即使内容相同，也不能掩盖新保存失败。

## 使用
1. 在 Mac SSClip 生成并官方签名 `SSClip发送.shortcut`，在 iPhone 替换同名快捷指令。只需一个快捷指令；保留名称 **SSClip发送**，内部重新导入入口使用同名调用。
2. 没有任何兼容状态文件时，首次选择自己的管理端连接 JSON，确认 HTTPS 地址。注册后保存并读回验证，本次不读取或发送剪贴板。
3. 日常复制纯文本，运行后每次选择本次接收设备：Mac。取消不发送，不保存默认目标。
4. 设备列表末尾“更换连接配置…”重新导入；可解析的配置/注册错误也提供重新导入或取消。取消不改原配置。

## 安全与限制
- 连接配置包含明文 API Key，仅保存在本人 iCloud 私人文件夹；不要上传状态文件、配置内容或分享运行详情。
- 同一 iCloud 账号可共用连接配置。所有快捷指令使用本站共享逻辑发送源 `ios-shortcut-sender` / “iOS 快捷指令”，`can_receive:false`，不是物理手机身份；不读写旧 phone-id 文件。各 iOS 的接收由独立 Bark 目标区分。
- 每次读取新设备列表，以名称＋完整 ID 区分同名设备；仅允许 Mac，排除显式 `can_receive:false` 及所有 iOS/Bark 目标。
- 空内容、包含 API Key 的任意文本、疑似完整配置 JSON 均阻止发送；图片/文件不 OCR、不读内容上传。文本类型目前安全支持中英文标签。
- URL 只允许 HTTPS 根地址；本模板不能保证原生 HTTP 不跟随重定向，只连接自己信任控制的服务。
- 正文 32 KiB UTF-8 限制由服务端执行；消息 20 分钟有效。成功仅说明服务端接受，不代表接收设备已收到或复制。失败不自动重发。
- 原生文件、网络或 JSON 解析错误可能由系统中止；模板不假称可捕获全部错误。失败提示不显示凭据值。

## 验证事实
- 526 个原生动作；3105 项结构/隐私/实际生成动作检查通过。
- `test_persistence_actions.py` 11 个测试组：实际 plist 三次冷启动、全部兼容文件名、canonical 优先、显式命名在替换/追加文本后缀模型下稳定、旧文件不能掩盖保存失败、错路径/provider及四项读回不符均失败。
- 负回归 fixture 提取自实际交付 `e4a4182c` 资源（SHA `92116684…`），记录未命名 Text→`.json` 保存动作，证明两种文本扩展名策略会使旧 loader 找不到文件。fixture 不含真实凭据。
- 模型明确区分文件名策略与原生提供器行为，不模拟 iCloud 权限/延迟，不等于新版 iPhone 实测通过。根因已有用户文件名证据，但本修复版仍需用户替换后连续运行验证。
- Cherri v2.3.0、禁用 derive UUID、全部字典键显式 getvalueforkey。unsigned 资源本身不可当作现成已签名安装文件。

日常成功仅提示“已提交 → 名称”，设置完成提示“连接已保存”。这些是服务端提交状态，不承诺对方已复制；安全说明保留在本文，不重复打断日常操作。Mac 客户端仍可发送到各自 Bark iOS；本 iOS 快捷指令不提供 iOS→iOS。
